01그림 한 장

지휘 세션은 하나다. 도구는 능력으로 등록된다. 기기 이름이 아니라 "무엇을 할 수 있나"로 부른다.

지휘 세션판단 · 분해 · 합치기
대화 맥락은 여기에만 있다
heavy홈맥 셸 — 빌드·렌더·전수 스캔
judge홈맥 가벼운 작업자 — 요약·분류·검토
browser에어 cmux 브라우저 — 읽기·로그인 상주
phone다음 도구 후보 — 휴대폰
gpu다음 도구 후보 — 원격 GPU 서버
왜 "세션 공유"가 아니라 "도구 등록"인가. 세 기기가 한 세션을 동시에 진행하면 기록이 갈라진다(한 파일에 둘이 쓴다). 반대로 기기를 MCP 도구로 등록하면, 세션은 하나인 채로 도구 호출만 다른 기기에서 실행된다. Claude 입장에서는 "Read·Bash 옆에 도구가 몇 개 늘어난 것"뿐이다 — 이것이 하네스를 넓히는 가장 범용적인 방법이다.

02일곱 원칙

전부 2026-10-08~09 실측에서 나왔다. 숫자가 없는 원칙은 넣지 않았다.

1

능력으로 부른다

"홈맥에서 해"가 아니라 "heavy 로 해". 기기는 바뀌어도 능력 이름은 남는다. 새 기기가 생기면 능력을 하나 더 등록할 뿐, 일하는 방식은 그대로다.

근거: multimac 도구 설명에 "에어는 브라우저, 판단은 홈맥"을 적어 두자 새 세션이 스스로 그 순서로 골랐다
2

싼 것부터 쓴다

보내기 전에 "이건 몇 단계인가"를 먼저 묻는다. 할 일이 정해진 건 LLM 없이(T0), 판단이 조금이면 Haiku(T1), 어려우면 강한 모델(T2), 대화 맥락이 꼭 필요할 때만 복제(T3).

근거: 같은 동시 분배가 Workflow 대리인 36초·토큰 약 22만 → batch 6.2초·토큰 0
3

맥락은 통째로 복제하지 말고 요약해서 건넨다

작업자는 대화를 모른다. 필요한 것만 브리프 한 장으로 건넨다. 브리프는 한 번 쓰고 여러 작업자가 같이 쓴다.

근거: 같은 요약 작업 — 대화 복제 $2.14 vs 브리프(약 1,000자)+Haiku $0.0146, 147배
4

결과는 짧게, 원본은 파일로

지휘 세션이 받는 건 20줄 이내 요약과 경로. 긴 결과가 지휘 맥락에 쌓이면 그 뒤 모든 턴이 비싸진다 — 장기적으로 가장 큰 비용이다.

근거: 작업자 규칙에 "20줄 이내, 긴 건 파일로"를 넣어 둠. 실전 재현에서 카드 원문은 홈맥 파일, 지휘 세션엔 제목만
5

동시 실행은 배치로, 대리인 없이

여러 기기 일을 동시에 할 땐 batch 한 번. "기기마다 에이전트 하나"는 대리인마다 기본 맥락을 다시 싣는 낭비다. Workflow는 항목마다 LLM 판단이 필요할 때만.

근거: batch 3기기 0.9초 · 실전 1단계(스캔+브라우저) 7.7초
6

기록을 남긴다

모든 호출의 기기 · 시작 · 끝 · 비용을 trace로 남긴다. 디버깅, 회고, 영상까지 같은 기록에서 나온다.

근거: 실전 축약 재현의 43초가 단계별 기기·시각·비용으로 남아, 어느 단계가 얼마를 썼는지 그대로 다시 셀 수 있다
7

되돌릴 수 없는 일은 지휘 세션에서

원격 작업자에는 전역 안전 훅이 없다. 삭제 · 발송 · 덮어쓰기는 원격으로 보내지 않는다. 원격 도구는 빠르고 싸지만, 되돌릴 수 없는 결정은 지휘 세션에만 있다.

근거: 가벼운 작업자 = 빈 설정(훅 0개). 안전 규칙은 시스템 프롬프트 몇 줄뿐

04작업 추가 레시피

새 일을 받았을 때 지휘 세션이 하는 순서. 여섯 단계가 한 번의 batch 두세 번으로 끝난다.

  1. 쪼갠다 — 컨텍스트 경계로"구현·테스트·리뷰"가 아니라 "무엇을 읽고 무엇을 판단하나"로 나눈다. 읽기는 나누고 쓰기는 모은다.
  2. 등급을 매긴다 — T0~T3각 조각에 사다리 단계를 붙인다. T0가 많을수록 싸고 빠르고 재현된다.
  3. 능력에 배정한다heavy · judge · browser. 보내기 전에 status 로 메모리 확인.
  4. 브리프를 쓴다판단 조각(T1·T2)이 있으면 배경을 한 장으로. 여러 작업자가 같이 쓴다.
  5. batch 로 보낸다같은 단계의 조각은 한 번에. 앞 단계 결과가 다음 단계 입력이면 단계 사이에서만 기다린다.
  6. 지휘 세션이 합친다 — 그리고 trace중복을 묶고, 한계를 적고, 결정은 여기서. 되돌릴 수 없는 마무리(발송·삭제·게시)도 여기서만.
# 실전 예: "최근 세션 기록에서 개인 사이드 프로젝트 후보 찾기" (실측 43초 · 작업자 $0.226)

       profile browser  read_url "<공개 프로필 페이지>"          # T0 · 7.4초
batch  cards1..3  judge ask -m haiku -b brief.md "후보 5개씩 카드로"     # T1 × 3 · 동시 23초
지휘    카드 병합 → 같은 프로젝트 묶기 → 최종 3                         # 결정은 지휘 세션에서

05도구 추가 레시피

"기기를 도구로"가 범용인 이유. 셸 명령 하나로 할 수 있는 능력이면 무엇이든 도구가 된다.

  1. 능력 하나를 셸 명령으로예: GPU 렌더 = ssh gpu "python render.py". 사람이 터미널에서 되는지부터.
  2. mm 에 서브명령으로호스트·인자 검증, 출력 길이 제한, 실패 시 짧은 오류. 위험한 인자는 형식으로 막는다(예: surface:N 만 허용).
  3. MCP 도구로 등록도구 설명이 곧 라우팅 규칙이다. "언제 쓰는지 · 언제 쓰지 않는지 · 얼마나 드는지"를 설명에 적는다. Claude는 그걸 읽고 고른다.
  4. status 에 얹는다새 도구의 상태(살아 있나·여유 있나)를 한 줄로. 보내기 전 판정이 가능해야 도구다.

"이 보고서 수치 맞는지 다른 눈으로 봐 줘"verify_judge (sonnet) → 내보내기 직전 verify_check
"이 페이지들 읽고 요약해 줘"batch[read_url × N] → ask haiku + brief
"무거운 거 알아서 돌려 줘"auto_dispatch("heavy", …)

06하루 운용 예시

"세 대를 쓰는 느낌"은 기기를 의식하지 않을 때 난다. 말로 시키면 능력이 알아서 붙는다.

아침

"지난주 세션 기록 정리해 줘" — heavy가 기록 전수 스캔(T0), judge 셋이 묶음별 요약(T1), 지휘가 주간 정리 초안으로 합침.

오전

"이 레포 분석해 줘" — heavy가 클론·집계(T0), browser가 README·릴리스 페이지 읽기(T0), judge가 축별 요약(T1), 지휘가 시나리오 작성(T2는 지휘 자신).

오후

앱 개발 — 편집은 노트북, 테스트·빌드는 heavy, 결과물 판정은 다른 모델의 judge(생성자·검증자 분리를 싸게).

저녁

영상 렌더 — render 도구로 홈맥에 보내고 노트북은 계속 Claude 작업. 무거운 일이 한 기기에서 겹치지 않는다.

상시

로그인된 사이트 — browser 도구(에어)에 상주. 노트북 cmux 탭이 쌓이지 않는다.

06+도구를 만들며 배운 것

검증자가 잡아낸 것들. 원칙을 다듬은 실측이다.

!

싼 판정은 흔들린다

같은 파일·같은 기준을 Haiku로 두 번 판정했더니 fail 과 pass 로 갈렸다. 장부는 "판정이 옳다"가 아니라 "그때 그 판정자가 그렇게 말했다"는 기록이다. 중요한 판정은 Sonnet 으로, 또는 두 번.

!

검증자는 진짜로 잡는다

verify 도구가 첫 실행에서 프로젝트 문서의 모호한 표현(후보 수와 카드 수를 섞어 쓴 것 — 실제는 후보 15 → 카드 5 → 프로젝트 3)을 찾아냈다. 만든 쪽은 못 봤던 것이다.

!

환경 차이는 경로가 아니라 런타임에서 터진다

홈맥의 기본 python 에는 렌더 후처리에 필요한 라이브러리가 없었다. render 도구는 원격 PATH 맨 앞에 필요한 python 을 고정해 해결했다. 도구를 만들 땐 "그 기기에서 그 명령이 정말 도는가"부터 확인한다(도구 추가 레시피 1단계).

!

같은 입력, 다른 결과

mine 을 다시 돌리면 카드 수가 달라졌고, 비용도 $0.30~0.35 사이에서 움직였다. LLM 단계가 들어간 도구의 실측은 한 번의 값이 아니라 범위로 적는다.

07하지 말 것

하고 싶어지는 것대신
세 기기가 한 세션을 동시에 진행세션은 하나, 기기는 도구. 세션을 다른 기기로 옮길 땐 한쪽을 끝내고 넘긴다
기기마다 에이전트를 하나씩 띄워 대화시키기batch 한 번. 대리인은 맥락을 다시 싣는 비용
대화를 통째로 복제해 넘기기브리프 한 장 (147배)
원격 결과를 전부 지휘 세션으로 가져오기20줄 요약 + 파일 경로
8GB 기기에 판단 작업자 띄우기가벼운 기기는 T0 도구(브라우저)으로만
원격에서 삭제·발송지휘 세션에서만. 원격 도구에는 안전 장치가 없다
