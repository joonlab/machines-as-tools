# 원칙 — 일곱 원칙 · 비용 사다리 · 하지 말 것

전부 실측에서 나왔다. 숫자가 없는 원칙은 넣지 않았다. 비용은 API 단가 환산이다.

## 그림 한 장

지휘 세션은 하나다. 도구는 능력으로 등록된다. 기기 이름이 아니라 "무엇을 할 수 있나"로 부른다.

| 능력 | 지금 맡은 도구 | 하는 일 |
|---|---|---|
| `heavy` | homemac 셸 | 빌드 · 렌더 · 전수 스캔 |
| `judge` | homemac 가벼운 작업자 | 요약 · 분류 · 검토 |
| `browser` | air cmux 브라우저 | 페이지 읽기 · 로그인 상주 |
| (후보) `phone` | 휴대폰 | 다음 도구 후보 |
| (후보) `gpu` | 원격 GPU 서버 | 다음 도구 후보 |

**왜 "세션 공유"가 아니라 "도구 등록"인가.** 세 기기가 한 세션을 동시에 진행하면 기록이 갈라진다. 한 파일에 둘이 쓰기 때문이다. 반대로 기기를 MCP 도구로 등록하면, 세션은 하나인 채로 도구 호출만 다른 기기에서 실행된다. Claude 입장에서는 Read·Bash 옆에 도구가 몇 개 늘어난 것뿐이다. 나는 이것이 하네스를 넓히는 가장 범용적인 방법이라고 본다.

## 일곱 원칙

### 1. 능력으로 부른다

"홈맥에서 해"가 아니라 **"heavy 로 해"**. 기기는 바뀌어도 능력 이름은 남는다. 새 기기가 생기면 능력을 하나 더 등록할 뿐, 일하는 방식은 그대로다.

- 근거: multimac 도구 설명에 "에어는 브라우저, 판단은 홈맥"을 적어 두자, 새 세션이 스스로 그 순서로 골랐다.

### 2. 싼 것부터 쓴다

보내기 전에 **"이건 몇 단계인가"**를 먼저 묻는다. 할 일이 정해진 건 LLM 없이(T0), 판단이 조금이면 Haiku(T1), 어려우면 강한 모델(T2), 대화 맥락이 꼭 필요할 때만 복제(T3).

- 근거: 같은 세 기기 동시 분배가 Workflow 대리인으로는 36초·토큰 약 22만, `mm batch` 로는 6.2초·대리인 토큰 0 이었다.

### 3. 맥락은 통째로 복제하지 말고 요약해서 건넨다

작업자는 대화를 모른다. 필요한 것만 **브리프 한 장**으로 건넨다. 브리프는 한 번 쓰고 여러 작업자가 같이 쓴다.

- 근거: 같은 요약 작업이 대화 복제로는 $2.14, 브리프(약 1,000자)+Haiku 로는 $0.0146 이었다. 약 147배 차이다.

### 4. 결과는 짧게, 원본은 파일로

지휘 세션이 받는 건 **20줄 이내 요약과 경로**다. 긴 결과가 지휘 맥락에 쌓이면 그 뒤 모든 턴이 비싸진다. 장기적으로 이게 가장 큰 비용이다.

- 근거: 작업자 규칙에 "20줄 이내, 긴 건 파일로"를 넣어 두었다. 실전 축약 재현에서 카드 원문은 홈맥 파일로 남고, 지휘 세션에는 제목만 왔다.

### 5. 동시 실행은 배치로, 대리인 없이

여러 기기 일을 동시에 할 땐 **batch 한 번**. "기기마다 에이전트 하나"는 대리인마다 기본 맥락을 다시 싣는 낭비다. Workflow 는 항목마다 LLM 판단이 필요할 때만 쓴다.

- 근거: 단순 3기기 batch 0.9초. 실전 1단계(스캔+브라우저) 7.7초.

### 6. 기록을 남긴다

모든 호출의 **기기 · 시작 · 끝 · 비용**을 trace 로 남긴다. 디버깅, 회고, 영상까지 같은 기록에서 나온다.

- 근거: 실전 축약 재현의 43초가 단계별 기기·시각·비용으로 남아 있어서, 어느 단계가 얼마를 썼는지 그대로 다시 셀 수 있다.

### 7. 되돌릴 수 없는 일은 지휘 세션에서

원격 작업자에는 전역 안전 훅이 없다. **삭제 · 발송 · 덮어쓰기**는 원격으로 보내지 않는다. 원격 도구는 빠르고 싸지만, 되돌릴 수 없는 결정은 지휘 세션에만 있다.

- 근거: 가벼운 작업자는 빈 설정 디렉터리로 뜨므로 훅이 0개다. 안전 규칙은 시스템 프롬프트 몇 줄뿐이다.

## 비용 사다리

원칙 2의 실물이다. 위로 올라갈수록 비싸고 느리다.

| 단계 | 비용 | 언제 | 도구 |
|---|---|---|---|
| **T0 · 결정론** | LLM 0 | 무엇을 할지 이미 정해짐. 빌드·렌더·스캔·페이지 읽기 | `run` `read_url` `browser` |
| **T1 · 가벼운 판단** | 1~3센트 | 판단이 조금 필요. 요약·분류·카드 | `ask` Haiku + 브리프 |
| **T2 · 어려운 판단** | 수 센트 | 판단이 어렵거나 긴 작업. 설계 | `ask` Sonnet/Opus, 이어서 시킬 땐 같은 작업자 |
| **T3 · 맥락 복제** | $1~2+ | 브리프로 옮길 수 없는 미묘한 대화 맥락이 꼭 필요할 때만 | `fork` |

운영 규칙:

1. 동시 실행은 `batch`. Workflow 는 항목마다 LLM 판단이 필요하고 항목이 많을 때만 쓰고, 그때도 대리인은 Haiku 로 두고 `batch` 를 부르게 한다.
2. 브리프는 지휘 세션이 한 번 쓰고 여러 작업자가 같이 쓴다. 분신 대신 브리프가 기본이다.
3. 결과는 20줄 이내로 돌려받는다.
4. 이어서 시킬 일은 같은 작업자에게 보낸다. 새로 쓰는 캐시가 수백 토큰(실측 225)으로 끝난다.
5. 8GB 기기는 T0 브라우저 도구 전용이다. 판단 작업자는 홈맥에 둔다.

## 하지 말 것

| 하고 싶어지는 것 | 대신 |
|---|---|
| 세 기기가 한 세션을 동시에 진행 | 세션은 하나, 기기는 도구. 세션을 다른 기기로 옮길 땐 한쪽을 끝내고 넘긴다 |
| 기기마다 에이전트를 하나씩 띄워 대화시키기 | batch 한 번. 대리인은 맥락을 다시 싣는 비용이다 |
| 대화를 통째로 복제해 넘기기 | 브리프 한 장 (약 147배 쌌다) |
| 원격 결과를 전부 지휘 세션으로 가져오기 | 20줄 요약 + 파일 경로 |
| 8GB 기기에 판단 작업자 띄우기 | 가벼운 기기는 T0 도구(브라우저)으로만 |
| 원격에서 삭제·발송 | 지휘 세션에서만. 원격 도구에는 안전 장치가 없다 |
| 중요한 판정을 Haiku 한 번으로 끝내기 | Sonnet 으로, 또는 두 번. 같은 입력에 fail/pass 가 갈렸다 |
