# 배운 것 — 도구를 만들며, 그리고 판정 과정에서

원칙을 다듬은 것은 계획이 아니라 틀린 예상이었다. 여기에는 실행해 보고 뒤집힌 것, 검증자가 잡아낸 것을 적는다.

## 1. 판정 과정의 반전들

### 반전 1 — "같이 쓰기"가 아니라 "나눠 실행하기"였다

처음 질문은 "맥 세 대가 세션 하나를 같이 쓸 수 있나"였다. 답은 불가였다. 세션은 한 프로세스가 기록 하나에 이어 쓰는 구조다. 그런데 이 "불가"가 오히려 출발점이 됐다. Claude 의 추론은 서버에서 돌고, 기기 RAM 을 먹는 건 도구라는 걸 알게 됐기 때문이다. 나눠야 할 것은 대화가 아니라 실행이었다.

### 반전 2 — 맥락을 통째로 넘기는 게 가장 비쌌다

분신(fork)은 작동했다. 다른 기기에서 내 대화를 그대로 이어받아 답했다. 하지만 26만 토큰 세션 한 번에 $2.14 였다. 결론에 필요한 것만 약 1,000자 브리프로 써서 Haiku 작업자에게 넘기자 $0.0146 이었다. 약 147배다. "맥락을 다 주면 더 잘하겠지"는 비용 앞에서 기본값이 될 수 없었다.

### 반전 3 — 대리인은 공짜가 아니다

기기마다 대리인 에이전트를 붙이는 건 자연스러워 보였다. 그러나 대리인마다 기본 맥락을 다시 실었고, 세 개가 약 22만 토큰을 썼다. 시간도 36초였다. 지휘 세션이 batch 한 번으로 직접 뿌리자 6.2초, 대리인 토큰 0 이었다. 단순한 명령을 나눠 보내는 데는 에이전트가 필요 없었다.

### 반전 4 — 작업자의 비용 대부분은 "작업"이 아니라 "설정"이었다

같은 단순 작업에 기본 구성 작업자는 95,209 토큰을 썼다. 대부분 전역 설정·메모리·스킬·도구 정의였다. 빈 설정 디렉터리에 도구를 줄이자 26,934 토큰이 됐다. 작업자를 싸게 만드는 건 모델을 바꾸는 것보다 싣는 것을 줄이는 쪽이 먼저였다.

### 반전 5 — 가장 가벼운 모드는 내 로그인 방식으로는 못 쓴다

`--bare` 최소 모드를 기대했지만 구독 로그인으로는 쓸 수 없었다. API 키 전용이다. 문서에 있는 옵션이 내 환경에서 되는지는 돌려 봐야 안다.

## 2. 도구를 만들며 배운 것

### 싼 판정은 흔들린다

같은 파일·같은 기준을 Haiku 로 두 번 판정했더니 **fail 과 pass 로 갈렸다.** 장부가 동결하는 것은 "판정이 옳다"가 아니라 "그때 그 판정자가 그렇게 말했다"는 기록이다. 그래서 중요한 판정은 Sonnet 으로 하거나 두 번 한다. 기준을 "X 가 있으면 fail"처럼 둘 중 하나로 가를 수 있게 쓰는 것도 도움이 된다.

### 검증자는 진짜로 잡는다

verify 도구가 첫 실행에서 프로젝트 문서의 모호한 표현을 찾아냈다. 실전 재현 결과를 적으면서 후보 수와 카드 수를 섞어 쓴 표현이었다. 실제 흐름은 후보 15 → 카드 5 → 프로젝트 3 이다. 만든 쪽은 보지 못했던 것이다. 생성자와 검증자를 나누는 것은 원칙이 아니라 실제로 값이 있는 일이었다.

### 환경 차이는 경로가 아니라 런타임에서 터진다

render 도구를 만들 때 홈맥의 기본 python 에는 렌더 후처리에 필요한 라이브러리가 없었다. 원격 PATH 맨 앞에 필요한 python 을 고정해서 해결했다. 같은 명령이 기기마다 같은 결과를 낸다고 가정하면 안 된다. 도구를 만들 땐 "그 기기에서 그 명령이 정말 도는가"부터 확인한다(도구 추가 레시피 1단계).

### 같은 입력, 다른 결과

mine 을 다시 돌리면 카드 수가 달라졌고, 비용도 $0.30~0.35 사이에서 움직였다. LLM 단계가 들어간 도구의 실측은 **한 번의 값이 아니라 범위**로 적는다.

### 도구가 스스로 멈출 줄 알아야 한다

71초 컨셉 영상을 홈맥에서 렌더하는 도중, 홈맥 부하가 급등했다. 렌더러는 115초 동안 스스로 일시정지했다가 부하가 내려가자 재개했다. 다른 기기에 일을 보낸다는 건, 그 기기의 다른 일과 겹칠 수 있다는 뜻이다. 내가 커널 패닉을 겪은 이유가 바로 그 겹침이었다.

### 도구 설명이 곧 라우팅 규칙이다

multimac 도구 설명에 "에어는 브라우저, 판단은 홈맥"을 적어 두자, 새 세션이 스스로 그 순서로 골랐다. 그래서 도구를 추가할 때 설명에 "언제 쓰는지 · 언제 쓰지 않는지 · 얼마나 드는지"를 반드시 적는다. 코드보다 그 세 줄이 Claude 의 선택을 더 많이 바꾼다.

### 위험한 인자는 형식으로 막는다

원격 탭 닫기는 인자가 비면 엉뚱한 탭이 닫힐 수 있다. 그래서 `close_tab` 은 `surface:N` 형식만 받는다. 원격 작업자에는 안전 훅이 없으니, 도구 쪽에서 형식으로 막는 것이 마지막 방어선이다.

### 만들고 검증하는 일도 같은 원칙으로

다섯 도구를 만들 때 도구마다 만드는 에이전트와 맥락을 공유하지 않는 검증 에이전트를 짝지었다. 새 도구는 `mm` 을 고치지 않고 기본 동작(run·ask·batch·read-url)을 조합했다. 서로 같은 파일을 건드리지 않으니 동시에 만들어도 충돌하지 않았다. 다섯 개 모두 검증을 통과했고, 도구는 8개에서 19개가 됐다.

## 3. 아직 모르는 것

- 기기 간 프롬프트 캐시가 공유되는지. 버전 차이 가설만 있다.
- Haiku 의 실제 단가. 홈맥 claude 구버전이 Sonnet 단가로 계산했을 가능성이 있다.
- 여러 세션이 동시에 auto 로 같은 기기에 몰릴 때의 동작.

자세한 숫자와 조건은 [benchmarks.md](benchmarks.md)에 있다.
